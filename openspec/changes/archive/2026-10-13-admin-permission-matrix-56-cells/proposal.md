# 權限矩陣擴為 56 格：五個新鍵登錄待啟用、名冊改歸成員管理鍵

對應 Spec: specs/admin/007-role-settings/spec.md

## Why

Issue #1270（2026-10-12 權限矩陣唯讀稽核的增鍵單）。

有幾項會寫入資料、或影響資料集分母的操作，目前在 V1 矩陣裡沒有對應的鍵：

- 任務生命週期命令：發布、退回 draft、結案、重試 IAA、停用資料隔離。
- 刪除 draft 任務。
- 最終例外池的四種處置。
- 名冊為空時，由專案負責人裁定爭議。
- Super Admin 檢視全平台統計。

授權判斷規則最後一條與 ADR-037 都禁止借用其他鍵，所以正式實作時，這些操作只能一律拒絕，或繞過矩陣。另外，審核名冊（`reviewer_ids`／`arbiter_ids`）目前跟著 `OVERVIEW_EDITABLE_FIELDS` 歸在 `task.detail.edit`，但名冊在性質上屬於「誰在這個任務裡擔任什麼角色」，與 `task.members.manage` 管的範圍相同。

維護者裁定（2026-10-12，issue #1270 預期調整表）：五個新鍵全部採用、預設停用；名冊改歸 `task.members.manage`；資料集重綁留在 `task.detail.edit`。

**「預設停用」的解讀**（本 change 採用，PR 說明同步交代）：

- 五個鍵登錄進白名單，並定案層級、操作對應與目標種子（任務層 PL ✅／RV ❌／AN ❌；`admin.platform_overview.view` 為 SA ✅／user ❌ 固定格），矩陣因此儲存 56 列。
- 五個鍵的狀態是「已登錄、待啟用」。依 ADR-037 新鍵程序，四項審查（層級、操作對應、完整種子、安全測試）中，本 change 完成前三項；安全測試要等正式後端實作並有 runtime 證據後，由另一個經審查的 change 確認。在那之前，任何以這五個鍵做的授權判斷 MUST 依未知鍵拒絕。
- 對應的操作在待啟用期間維持既有的角色與資源閘門，不得改成只憑矩陣放行。
- 名冊改歸的 `task.members.manage` 是現役鍵，改歸直接生效。

**為什麼不走 Lightweight Path**：本 change 修改授權契約（FR-011）與成功標準（SC-011 的格數），並新增一則可測 AC，超出「只釐清」的範圍。

**分級：MINOR。** FR-011 與 SC-011 原文逐字保留，只在後面補修訂段。新鍵依既有的新鍵程序登錄。名冊改歸屬於維護者裁定的操作對應修訂，對 PL 的實際權限沒有影響（PL 兩格皆 ✅）。沒有移除或推翻任何 FR／AC。

## What Changes

- **修訂 FR-011**：補一段 v1.3.0 修訂。
  - 列出五個新鍵、各自的層級，以及 56 列（10 平台鍵 × 2 + 12 任務鍵 × 3）。
  - 規定「已登錄、待啟用」狀態的拒絕語意。
  - `admin.platform_overview.view` 依新 `admin.*` 鍵程序，原子建立固定格。
  - 名冊改歸 `task.members.manage`。
  - 新增不帶 ID 的情境，涵蓋每個新鍵的安全邊界：非 PL 被拒、membership 失效被拒、狀態不符被拒、SA 路徑另測、待啟用鍵一律拒絕。
- **修訂 SC-011**：格數 42 → 56（原文逐字保留，補修訂段）。
- **正典回寫**（gate 4）：
  - 白名單加五列。
  - 兩張矩陣表加列。
  - 授權判斷規則的格數條改為 56，最後一條改寫為「已登錄、待啟用」與名冊改歸。
  - `task.members.manage` 的說明補上名冊。
  - 新增一則 AC（編號接續使用者故事 3 現行最大者 AC-3.4）。
  - FR-011／SC-011 各補修訂段。
  - 版號 1.2.1 → 1.3.0，Changelog 加一列。

**非目標**：

- 不實作正式後端，也不啟用五個新鍵（啟用需要另一個經審查的 change 加 runtime 安全測試）。
- 不改 014／010／015／012 以外的規格；這四份的「操作 → 鍵」條文由各自的 change 或 Lightweight PATCH 承接。
- 不改 audit drawer 空狀態（由 #1189 負責）。

## Capabilities

`admin` — 權限鍵白名單、角色 × 權限矩陣與新鍵啟用程序。
