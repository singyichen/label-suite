# Account Session Naming Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓 #1160 的一次登入候選表、refresh token FK、明確登出時間在正典與 NoteCraft 使用一致且常見的命名。

**Architecture:** 先修改 account/foundation 正典與 Accepted ADR，經 OpenSpec delta 保存變更，再投影到實體字典、總帳、ER JSON 與 auth lifecycle 圖。JWT `sid`、安全撤銷行為、表的未部署狀態保持原契約；`logged_out_at` 專屬成功明確登出。

**Tech Stack:** Markdown 正典、OpenSpec CLI、Node `node:test`、NoteCraft `er-diagram-renderer`、Archify JSON→HTML。

**Spec:** `docs/superpowers/specs/2026-10-08-account-session-naming-design.md`

## Global Constraints

- 只規劃候選 schema，不改 backend runtime、ORM、migration 或 HTTP API。
- 新表名 `account_session`，新 FK 欄名 `refresh_tokens.session_id`；JWT claim `sid` 不改。
- `logged_out_at` 可空，只記可驗證的明確登出；安全作廢、到期與清 cookie 不產生登出時間。
- 當前文件說明用繁體中文；歷史 OpenSpec archive 不改寫；先 Red 後 Green。
- 遵循 `AGENTS.md` 四道 SDD 閘與英文 commit 格式；CLI 歸檔後逐一定位 canonical 引用。

## Review Focus

- access-only 登出成功：`logged_out_at` 與 `revoked_at` 同交易；以 Red 測試固定 account-020 FR-008 及字典說明。
- 無有效憑證僅清 cookie：`logged_out_at` 保持空；同一 Red 測試固定反例。
- 密碼／email 安全作廢：`revoked_at` 可有值，`logged_out_at` 仍空；同一 Red 測試固定語意。
- 舊 `family_id` 從現行 FK 消失，但 JWT `sid` 仍在；Red 測試同時查正典、JSON 與圖。
- NoteCraft 的關聯線只由真 FK 生成；Red 測試要求 `refresh_tokens.session_id.fk = account_session`，不產生第二個別名表。
